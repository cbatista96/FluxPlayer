## Native callback lifetime

LibVLC callbacks may run on native event threads. Do not call back into the player synchronously from those callbacks or dispose native media there. Metadata parsing uses a shared semaphore. After an awaited parse completes, `Task.Yield()` moves subsequent reads and disposal out of the inline native completion callback. Service disposal waits for active metadata parsing before releasing LibVLC.

UI changes are dispatched to WPF. A–B seeks and stop operations that might reenter LibVLC must also leave the native callback thread first. Preserve these boundaries when refactoring asynchronous code.

## Video presentation

VLC writes RV32 frames into a Windows shared-memory section. WPF presents that section as an opaque Bgr32 `InteropBitmap`. Pitch and line count are aligned for the native converter. Callback delegates remain rooted for the playback lifetime.

Display notifications are coalesced so at most one WPF invalidation is queued. Replacing a format defers retirement of the old section to allow WPF composition to finish. The mini player mirrors the existing bitmap; it does not create another decoder. Ambient light samples a small grid from the current section rather than copying a full frame.

This presentation path avoids full-frame managed copies on the UI dispatcher. Its actual cost still depends on resolution, decoding, memory bandwidth, WPF composition and hardware. Hardware decoding is requested where configured; the complete display path is not claimed to be a universal GPU zero-copy pipeline.

The format callback reports the original source FourCC before requesting RV32. VLC 3 can attempt to blend YUVA subtitles into an opaque DX11 surface before conversion, which fails. Only a detected Windows opaque surface with an active subtitle triggers the bounded software-decoder transition. Sources that already deliver CPU-compatible frames do not restart. The transition retains position, pause and up to 16 explicitly loaded subtitle sources; Stop and a new source cancel pending restoration. Disposal cancels and drains the operation before native objects are released. Recovery does not reintroduce a hardware profile on that source after subtitle compatibility fallback. A GPU-composed presentation path remains unimplemented.

## Startup and background work

- Load library state lazily. File enumeration and batch construction run outside the dispatcher.
- Bound initial playlist duration parsing to a small batch and skip the current playback item. Do not predecode the entire library at startup.
- Resolve actual audio/video tracks after opening; use filename extensions only as a provisional hint.
- Generate thumbnails on demand and keep expensive optional tools outside normal transport events.
- Keep FFmpeg conversion sequential, use bounded error capture and drain both redirected process pipes.
- Use tiered PGO for regular builds and ReadyToRun in the local publish profile. Trimming remains disabled because of WPF and native/reflection dependencies.
- The packaging script prepares the VLC plugin cache when possible to avoid repeated plugin scans.

These are implementation choices, not a guarantee of zero performance cost. Compare representative workloads before and after changes: cold/warm startup, time to first audio/frame, idle CPU, playback CPU, memory, seek responsiveness and large-library interaction. Record the machine and media details with measurements.

## Snapshot jobs

Capture requests are serialized and run outside the UI dispatcher. LibVLC 3 forces native snapshots to PNG, so JPEG/BMP output is explicitly encoded after the native completion event; changing a filename extension alone is insufficient. See the [upstream implementation](https://github.com/videolan/vlc/blob/3.0.21/lib/video.c#L136). Completion continuations run asynchronously, temporary files are cleaned up, and publication refuses to replace an existing image. Engine disposal cancels pending work before releasing native objects.

Scheduled captures are explicit bounded jobs. Each attempt completes before another delay starts, so slow encoding cannot accumulate queued requests. Paused, audio-only and busy playback are skipped. A schedule has no timer until the user starts it and ends when its image limit is reached or its window closes.

## Data and compatibility

The legacy ten-band VLC equalizer applies a fixed factor of 0.25 to its dry signal. The service offsets that attenuation by `20 * log10(4)` dB, so a flat displayed 0 dB matches bypass. Effective requested preamp is capped before conversion to the native ±20 dB range. ISO centers are retained, and equalizer updates run only on user changes or source initialization. See the [upstream filter](https://github.com/videolan/vlc/blob/3.0.21/modules/audio_filter/equalizer.c#L130).

Extended layouts use a C plugin built against the pinned VLC 3.0.21 SDK. It advertises the `equalizer` shortcut at higher priority and accepts only an enabled, valid 15/20/31-band configuration; the original module handles ten-band mode. Fifteen ISO centers use two-thirds-octave spacing; the 31-band layout uses one-third-octave spacing. The service forces module reselection only across the legacy/extended boundary. Changes within extended processing update a local 1 KiB memory map, using an odd/even sequence counter and memory barriers. Unchanged settings are deduplicated. A reader encountering an incomplete update retains its current coefficients instead of waiting. Native status acknowledges the applied sequence, rate, channels and effective preamp; readiness is distinct from active processing.

The filter processes interleaved FL32 in place with cascaded peaking biquads, using double-precision coefficients and history. Each nonzero band is independent; zero-gain sections are skipped and a flat, unity-gain block returns without a sample loop. Fixed history arrays support up to 31 sections and 32 channels; accepted rates are 8–768 kHz, with centers near/above Nyquist omitted. Coefficients use the peaking-filter form described by the [Audio EQ Cookbook](https://www.w3.org/TR/audio-eq-cookbook/#formulae), with fixed Q derived from each layout's octave spacing. This is a graphic EQ, not an arbitrary frequency/Q editor.

On configuration changes, old and new filter histories crossfade for 256 frames and the preamp ramps over a block. Flush clears history. Headroom estimation evaluates the combined response at 512 logarithmic frequencies plus the exact centers, then adds 0.25 dB where gain is present. It is not a true-peak limiter. These calculations run only on changes; the audio path performs no managed callback, waiting, heap allocation or file I/O. Mapping and filter storage are allocated when opening and released on close. The managed map outlives native engine disposal. The module frees VLC-owned strings through `libvlc_free` to preserve allocator ownership across C runtimes.

See [Native DSP measurements](NATIVE_DSP.md) for bounded response and processing-cost evidence. These measurements do not establish zero startup/playback overhead or a complete hardware matrix.

Per-media `audio-filter` options were measured to leave a compressor test signal unchanged in this pipeline. The previous normalization/compressor switches are therefore visibly planned rather than claimed as implemented. The [native equalizer setter](https://github.com/videolan/vlc/blob/3.0.21/lib/media_player.c#L2004) also replaces the audio-filter chain. A verified combined DSP chain remains pending; future work must test processed samples rather than only option persistence. Conversion normalization uses a separate FFmpeg path.

Channel routing uses the native player's `stereo-mode` setter, with values from the pinned SDK. Mono (7) and Original (0) are passed through LibVLCSharp's enum even though that older managed enum omits their names. See the [native setter](https://github.com/videolan/vlc/blob/3.0.21/lib/audio.c#L461) and [channel preparation](https://github.com/videolan/vlc/blob/3.0.21/src/audio_output/output.c#L375). Native Playing can precede decoded output initialization, so a bounded deferred pass checks at 100, 350 and 1,000 ms after a playback/settings/output change. It only reapplies a differing mode; Original gets one deferred application because it may resolve to a source-specific value. New requests supersede old revisions, and source changes, Stop and disposal invalidate stale work. Native callbacks only schedule this work. There is no recurring idle poll or managed sample processing in the application.

Subtitle track additions, removals and selection events only enqueue a coalesced dispatcher refresh; native callbacks never query the player directly. Collection replacement suppresses selection write-back, preserving the actual native selection and a single Disabled entry. External subtitle paths are converted to absolute file URIs before `AddSlave`, which requires a scheme.

Native default text styles are applied to the LibVLC instance at startup, matching the renderer's variable inheritance. Applying freetype options to individual media objects was verified to leave the default rendering unchanged in this pipeline. Style changes are therefore persisted for the next player start. Named styles are validated and bounded to 32 entries. No additional text renderer, per-frame managed styling or profile polling is introduced. See the [upstream FreeType options](https://github.com/videolan/vlc/blob/3.0.21/modules/text_renderer/freetype/freetype.c#L141) and [VLC 3 composition order](https://github.com/videolan/vlc/blob/3.0.21/src/video_output/video_output.c#L930).

The subtitle timing editor transforms text cues on demand using decimal scale/offset arithmetic. Parsing and SRT output are bounded to 16 MB and 100,000 cues. Exports finish in a temporary file before publication, and the editor requires a different path from the original. Live native delay and exported timing are independent; loading an exported copy clears live delay. This tool does not introduce a per-frame scan or idle timer.

TagLibSharp is used only by explicit tag edits, without decoding media properties. Each save finishes before cancellation is honored and reopens the file to verify selected fields. This avoids the empty-field behavior of LibVLC 3's [metadata writer](https://github.com/videolan/vlc/blob/3.0.21/modules/meta_engine/taglib.cpp#L1172). Batch editing skips sources loaded in the player, processes one file at a time and reports each result. Successful writes refresh indexed metadata and file stamps, with one library notification at job completion. Editing does not add a playback filter or background scanner.

Settings and library files belong to the current Windows user. Write changes through the service layer and preserve migration paths. Legacy preset names and query aliases remain accepted as compatibility data even though the public interface and documentation are English.

Personal library labels use immutable arrays, bounded to 32 names of 64 characters per entry. Explicit batch edits validate the complete selection before mutation, serialize under the index gate on a worker, and publish through a unique temporary file. Failure restores the prior records; cancellation is observed before commit. Backup label unions are preflighted before any imported entry changes. Queries compile exact label tests once per search; no label scan is added to playback or idle processing.

External navigation chapters are parsed only on explicit request. Input is bounded to 4 MiB, 10,000 chapter atoms and XML depth 32; XML resolvers are disabled and declarations control byte decoding. A draft must pass complete time/title/duration validation before replacing session navigation. Copy exports use a unique temporary file and refuse to replace an existing destination. The format scope follows [MKVToolNix's simple and XML chapter documentation](https://mkvtoolnix.download/doc/mkvmerge.html#mkvmerge.chapters); ordered/linked playback and container metadata edits remain pending. The menu creates at most 200 items and sends larger lists to the virtualized editor, avoiding unbounded menu construction.

The full competitor research and private working reports are not distribution inputs. Public capability status is maintained in `FEATURES.md` and `FeatureCatalog`; unimplemented catalog entries must remain visibly planned.

Library browsing derives exact artist/album/personal-label facets from immutable index records on a worker. Artist/album values are trimmed and compared ordinally without case; labels retain their canonical values. Album choices are scoped to the selected artist, and label choices to the selected artist/album. A multi-label file contributes once to the total file count. Null criteria mean all values, while empty criteria mean missing metadata or no labels. Criteria are separate optional smart-playlist fields, preventing metadata names from being interpreted as query syntax. Older records omit these fields and retain their original behavior. Backup imports and saved criteria share validation. A new browse request cancels the previous worker, generation checks reject obsolete results, and dropdowns recycle their item containers. This does not add media reads, playback callbacks or an idle scanner.

Batch renaming runs only on explicit request, with at most 10,000 files and metadata reads on a worker. A complete preview/preflight checks unique targets, folders, extensions and source size/modification stamps. Each filesystem move and existing index-path replacement share the library scan gate and index gate, preserving indexed metadata against watcher scans. Loaded-source checks occur immediately before the move; successful results relocate queue/recent/bookmark/resume paths on the dispatcher. Jobs persist the library once and publish one notification. Cancellation preserves completed moves. This is sequential partial completion, not a filesystem transaction or an undo system, and adds no playback processing or idle work.

Per-file playback preferences are optional and disabled by default. The disabled path performs no file stamp read. An enabled source opening captures size/mtime once; explicit volume/track/subtitle changes update a bounded in-memory record, with no per-frame disk writes. The regular settings save publishes up to 1,000 records. Native track restoration waits for Playing/Paused and matches ID plus name, with once-per-source application guards; coalesced track notifications provide later opportunities when tracks appear. User choices supersede pending restoration. External subtitle reattachment is attempted once per source. Source changes reset pending state. A reset token prevents a saved Settings clear request from being resurrected by a later VM save. Volume restoration preserves mute and respects current boost limits. Identity uses stamps rather than content hashes; subtitle delays and output profiles remain separate.

MediaFolderBrowser enumerates one explicitly requested directory on a worker and classifies catalogued extensions without media decoding. Accepted entries are capped at 10,000, with a truncation indicator; directories remain visible under filename/type filters. Cancellation and generation checks prevent an obsolete read from publishing its result. The virtualized folder tool has no watcher or idle scan. Explicit Play calls the common VM transport independently of the automatic-opening preference; enqueue does not start transport. It does not mutate files or recursively traverse subfolders.

Advanced metadata uses immutable selective patches. Thirteen known field definitions centralize numeric validation and TagLib getters/setters; custom keys are bounded and stored as namespaced ID3v2 user text or Xiph comments. Unsupported custom containers reject the patch before Save. Other requested fields are reread after writing; failed verification is reported explicitly rather than treated as a successful format capability. Native formats may retain supported edits even when another requested field fails verification, so this is not rollback. Metadata property decoding is disabled and cover bytes are kept lazy/preserved. The reader and writer share the existing explicit metadata gate, outside playback callbacks. Tag templates are versioned, reject unknown JSON members, read at most 2 MB plus a sentinel byte, and validate before draft mutation. Exports use a unique temporary file and refuse replacement. Template files cannot select media paths or execute operations; applying a loaded draft remains an explicit action.

File organization reuses the sequential rename/index pipeline and a shared metadata token renderer. Preflight confines canonical targets below an existing root, preserves extensions, refuses cross-root drive/share paths and walks existing ancestors to reject reparse points. It does not provide an adversarial filesystem transaction. Metadata is read on an explicit worker preview, with property decoding disabled and pictures lazy. Per-file directory creation/move/index relocation occurs under the scan/index gates; UI path relocation happens after releasing them. Completed index mutations persist in a finally block even if a progress callback fails. No playback filter, idle poll or background organizer is added.

Library column views use a whitelist of 14 indexed properties, finite bounded widths, unique normalized positions and up to three sort descriptions. Title cannot be hidden; up to 16 named layouts are stored alongside the current view. Filter replacement captures/reapplies the live WPF layout and actual collection sort. Values such as duration/size use numeric sort members rather than formatted display strings. Named-view saves reload the latest settings before writing, and Settings preserves concurrently saved layouts unless explicitly resetting preferences. Storage failures do not publish a new in-memory layout and are reported to the player. No media reads or per-frame work are introduced by these layouts.

Virtual collections are immutable ID/parent/path records in the existing version-1 library store; old files omit Collections and remain compatible. Mutations clone/validate the bounded graph and publish under the library gate on a worker, with rollback on canceled/failed publication. Backup preflight validates parent/member references before index changes; matching sibling trees remap IDs before importing scoped playlists. File moves relocate memberships under the same index gate, and index removal prunes them. Hierarchy validation/choice generation and membership filtering run on workers. No watcher, media read or playback callback is added.

CueDocument is a bounded text-preserving parser, independent of the simple navigation reader. Known directives receive structural/frame checks; unrecognized statements remain inert text. Copy export parses again, rewrites only FILE/CDTEXTFILE reference spans, validates the rebased document and publishes a unique temporary file without replacement. Original documents and linked media remain untouched. Directive conventions were checked against the primary [libcue grammar](https://github.com/lipnitsk/libcue/blob/master/cue_parser.y); FluxPlayer does not embed that parser or claim full disc mastering semantics. UTF-8 decoding is strict, BOM imports are supported, and Windows-1252 is an explicit choice. Parsing and export are explicit worker operations.

ConversionOptions validates a bounded encoder-specific set before FFmpeg starts. Explicit output arguments override bitrate/quality presets, apply the requested sample rate/channel count and choose WAV integer codecs or FLAC precision. ArgumentList avoids shell interpretation. Existing sequential job scheduling, two FFmpeg threads, low process priority, temporary publication, cancellation and original-file preservation remain in use. The new controls do not install filters in the playback path or guarantee hardware output precision.

Settings actions declare an attached category, section and optional quick-access flag. The registry rejects uncategorized root actions. Settings groups the same source actions under six destination pages; the player context menu includes only the curated quick-access subset. Cloned menus copy header visuals and forward leaf actions once, avoiding WPF visual reparenting and duplicate command execution. Device, track, chapter and check state are rebuilt on menu opening. Live routing saves only the requested preference before applying it, preserving unrelated active transport/audio state; failed saves do not change native routing.

Playback session history is opt-in and profile-local. The disabled path creates no history file or timer. Source opening creates a draft, native Playing starts a Stopwatch, Paused stops it, and managed stop/switch/end/error/shutdown finalize checkpoints. Playing/Paused callbacks always defer native queries to the dispatcher, including callbacks raised synchronously inside native Play/Stop. Stopped also defers its native-state query until after returning from the callback, and ignores a stale notification while a replacement source is opening/playing. There are no history writes on TimeChanged or on the audio processing thread. Immutable checkpoints run in order on workers, and explicit clear discards the active draft before joining that same write chain so stale saves cannot restore cleared entries.

PlaybackHistoryService loads on demand, validates a versioned store (maximum 32 MiB/5,000 entries), serializes edits through a gate and publishes unique temporary files atomically before replacing its memory snapshot. Reads apply count/age limits without modifying disk; later checkpoints prune the stored set. Failed writes retain the previous store and cached records; malformed stores are preserved until an explicit clear. History filtering runs on demand with cancellation/debounce and generation guards. The virtualized history window totals playing time from session snapshots and can replay/resume or export a new JSON copy. Recorded paths are historical; automatic relocation, crash-proof journaling and verified audible-listen accounting are outside this feature.

MediaCatalogService is instantiated lazily per settings data directory. Its immutable snapshot stores up to 200 ordered saved lists and 1,000 user-entered stations. The store validates IDs, names, sources, revisions and aggregate bounds before a unique temporary-file publication (32 MiB maximum); memory changes only after successful publication. A serialized edit gate prevents overlapping writes. Playlist revisions detect outdated editors, and protected lists reject content/name/removal edits until a separate explicit unlock. Radio import is a single validated merge, retaining existing favorite/descriptive metadata; URI identity preserves path/query case. No catalog timer, native callback or automatic network fetch is installed.

The saved-media window filters on explicit search with debounce/generation checks and recycles list/track rows. Selection retains original entry indexes, preventing filtered edits from removing the wrong rows. Reordering requires one selected row and an empty query. Playback snapshots append available sources without changing saved lists; explicit Play bypasses the opening autoplay preference. Title lookup uses a dictionary instead of rescanning the entire imported list for each queue row. Native duration prefetch skips network sources, so enqueue does not create unsolicited connections.

Named playlist imports read EXTINF titles, numeric PLS fields and XSPF track locations/titles. Input is bounded to 32 MiB and 100,000 entries; XML entities are prohibited. The new saved-document path retains unavailable local references, while the existing playback importer continues to skip them. Copy exports preserve the format extension on their temporary filename and refuse existing destinations.

## Native effects, production jobs and task scheduling

AudioEffects is an immutable, bounded snapshot of sixteen effect types and their parameters. Settings are validated and durably saved before live publication. NativeDspBridge protocol 3 expands the per-player map to 4,096 bytes: the existing graphic EQ prefix remains, effect parameters follow at byte 280, the 8x8 matrix starts at byte 604, RMS target/boost/response occupy bytes 860-871, and acknowledgement/meter status starts at byte 1,536. The native seqlock publishes the complete configuration; native processing reports its applied sequence. Extended graphic EQ and effects share one filter. A first effect activation reopens the filter chain to allocate delay history; subsequent changes retain native block processing. Bypass preserves the flat fast path, and metering is enabled only for the open signal-path window. Native bounds and response/cost evidence are in [NATIVE_DSP.md](NATIVE_DSP.md).

FfmpegJob runs an explicitly installed executable through ArgumentList, drains diagnostics, bounds retained output, supports cancellation/process-tree cleanup and publishes unique completed copies without replacement. AudioAnalysis separates full-source RMS/loudnorm/replaygain branches from bounded onset/correlation tempo analysis. BatchConversion reserves unique names then uses 1–4 parallel workers. MediaProduction uses decoded/resampled ordered concat or whitelisted video/mobile profiles. These are explicit local jobs with reduced priority and bounded encoder threads; no analysis/conversion daemon starts with playback.

VideoViewport maps zoom/pan and a selected SBS/TB eye onto validated source coordinates. VlcWpfRenderer presents that rectangle of the existing section and applies anamorphic compensation/orientation through a WPF layout transform. Snapshot encoding applies the same crop, aspect compensation and orientation to the captured source frame. View state resets per source; orientation remains a session choice.

PlaybackSchedule uses the versioned ProfileDocument store, validates a maximum of 100 one-time or recurring tasks and atomically disarms due claims before dispatch. Claim identity is rechecked before replacing the queue. DST-ambiguous/invalid local times are rejected; missed tasks older than five minutes are recorded without running. The dispatcher timer exists only for armed tasks, with a bounded interval until the nearest deadline. VolumeFader interpolates at 40 ms on the dispatcher, shares mute state, and cancels on manual volume changes, Stop or shutdown. Recurring series retain local weekday/time and time-zone identity, advance after durable completion and skip invalid/ambiguous DST occurrences. Equal-time priorities dispatch higher values last. Alarm notices can be snoozed through a separate one-time task. No operating-system scheduler or wake service is created. See [the processing guide](AUDIO_VIDEO_PROCESSING.md) for the user-visible guarantees and limits.
